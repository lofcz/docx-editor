Import functions, error classes, and types from `@docx-editor.dev/docx-to-markdown`. For installation, see [DOCX to Markdown](/docs/2.x/export/markdown#install-the-converter).

## Convert a document

`exportMarkdown(source, options?)` returns `Promise<MarkdownExportResult>` and cleans up its own export session. Pass DOCX bytes (`Uint8Array` or Node.js `Buffer`) or a `HeadlessDocumentView`.

```ts
import { readFile } from 'node:fs/promises';
import { exportMarkdown } from '@docx-editor.dev/docx-to-markdown';

const result = await exportMarkdown(await readFile('contract.docx'), {
  displayMode: 'proposed',
  images: true,
});
```

## Set options

| Option | Default | Behavior |
| --- | --- | --- |
| `displayMode` | `'all-markup'` | `'proposed'` hides deletions. `'original'` hides insertions. Never modifies the DOCX. |
| `paragraphAppearance` | None | Supplies deterministic paragraph appearance defaults through the native style cascade. Does not change the source DOCX. |
| `images` | `false` | `true` for image links and bytes, or an object with `syntax`, `resolveUrl`, and `maxTotalBytes`. See [Images in Markdown exports](/docs/2.x/export/markdown/images). |
| `sourceMap` | `false` | Use `true` for native paragraph IDs and UTF-16 boundaries in logical Markdown. |
| `tableSyntax` | `'gfm'` | Use `'html'` for structured cells or `'auto'` for spans and rich cells. |
| `signal` | None | Cancels resource waits and later work at cancellation checks. |
| `resourceTimeoutMs` | `60000` | Positive finite timeout, in milliseconds, for each resource wait, including fonts. Not a total deadline. |
| `fonts` | None | Caller font sources or resolvers, before bundled substitutes. Requires DOCX bytes. |
| `fallbackFonts` | None | Font sources or resolvers after bundled substitutes. Requires DOCX bytes. |
| `fontPolicy` | `'best-effort'` | `'strict'` refuses font origin failures and missing static faces among candidate families. |
| `onFontResolution` | None | Receives the font report. The exporter does not await callback promises. |

`fontPolicy` and `onFontResolution` need byte input with default font resolution. With a live view or a custom measurer, they throw `TypeError`. For custom measurement, image decoders, and session controls, see the [complete option reference](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/api.md#options).

Import `ParagraphAppearanceContribution`, `ParagraphAppearanceContext`, `ParagraphAppearanceControl`, and `ParagraphAppearanceDefaults` from this package to type appearance callbacks.

## Read the result

| Field | Meaning |
| --- | --- |
| `markdown` | Continuous document Markdown. Joins split records and excludes repeated headers and footers. |
| `pages` | Physical pages in document order. Each has `id`, `number`, `markdown`, `headerMarkdown`, `footerMarkdown`, `comments`, and `trackedChanges`. |
| `pagination` | `source`, `scope`, Core `layoutRevision`, and `displayMode`. |
| `media` | Unique extracted images with bytes and occurrences. Empty when images are off. |
| `reviewArtifacts` | All comments and tracked changes, including artifacts without a page occurrence. |
| `reviewBindings` | Ranges that link review occurrences to generated Markdown strings. |
| `sourceMap` | Optional native text provenance for `markdown`. Includes source scopes, paragraph extents, and sparse text boundaries. |
| `fontResolution` | Resolved and substituted fonts, coverage, and origin failures. `null` when evidence is unavailable. |
| `warnings` | Content omissions, image placement fallback, and font problems. |

### Pages

- `page.number` is a one-based physical position, not a printed page label.
- `page.id` is valid only within this result.
- A blank sheet that sets section parity is a page with empty Markdown.
- Page Markdown includes local note definitions and labeled continuations. Use `result.markdown` for joined content.
- `pagination.layoutRevision` is a Core revision, not your file or package version.

### Comments and tracked changes

A page's `comments` and `trackedChanges` hold complete artifacts with at least one occurrence on that page. To count artifacts once, use `reviewArtifacts`. For page-local occurrences, filter on `occurrence.physicalPageNumber === page.number`.

The following loop prints the Markdown text that each review binding covers:

```ts
for (const binding of result.reviewBindings) {
  const projection = binding.projection;
  const text =
    projection.kind === 'document'
      ? result.markdown
      : result.pages[projection.pageIndex]![projection.field];

  for (const range of binding.ranges) {
    console.log(text.slice(range.start, range.end));
  }
}
```

| Binding field     | Values                                                                 |
| ----------------- | ---------------------------------------------------------------------- |
| `ranges`          | UTF-16 offsets, inclusive `start` and exclusive `end`, as in `slice()` |
| `coverage`        | `complete`, `partial`, or `none`                                       |
| range `precision` | `exact` or `containing-construct`                                      |

Check `coverage` and `precision` before you treat a mapping as exact. Editing or splitting the strings invalidates offsets. Artifacts without occurrences have no bindings.

### Warnings

Each warning has `code`, `message`, and optional `pageNumber` or `partName`. Store warnings with exported results.

| Code | Meaning |
| --- | --- |
| `omitted-drawing` | A drawing is not in the output. A chart without an exported image gets one, with at most five chart warnings per page plus one count. |
| `omitted-textbox` | Anchored text-box text is not in the output. |
| `font-origin-failed` | A font source failed. |
| `incomplete-font` | A family is missing static faces. |
| `content-scan-limit` | Content scanning stopped at a limit. |
| `image-placement-fallback` | An anchored image has no exact source position. |

An empty warning array does not certify visual parity with the source.

## Handle errors

| Error | When | Fields |
| --- | --- | --- |
| `DocumentOpenError` | The document is rejected. | `reason`, `detail` |
| `ExportResourceError` | Resource or layout failure. | `code`: `aborted`, `timedOut`, `nonConvergent`, `disposed`, `layoutInvariant`, or `layoutFailed` |
| `MarkdownMediaError` | Image extraction fails. | `code`; see [image errors](/docs/2.x/export/markdown/images#handle-failures-and-limits) |
| `MarkdownBundleError` | ZIP or folder output fails. | `code`; see [image errors](/docs/2.x/export/markdown/images#handle-failures-and-limits) |
| `TypeError` | Font policy or callback used with a live view or custom measurer. | None |

## Reuse a session

`exportMarkdownFrom(session, options?)` exports from an open session and leaves the session open. To export PDF and Markdown from one layout, see [Compare PDF and Markdown conversion](/docs/2.x/export/pdf/markdown-contract). For Markdown-only sessions, see [Reuse an export session](https://github.com/eigenpal/docx-editor/blob/main/packages/docx-to-markdown/docs/api.md#reuse-an-export-session).

## Limits

- `signal` cannot interrupt synchronous parsing or layout.
- Merged table cells are flattened. Nested tables use inline HTML.
- Images do not keep crop, rotation, or floating text wrapping. Images affect pagination even when extraction is off.
- For feature coverage, see [DOCX fidelity](/docs/2.x/docx-fidelity).

## Native text boundaries

Set `sourceMap: true` to map logical Markdown text to native paragraph positions. This option works with `exportMarkdown`, `exportMarkdownFrom`, and `exportMarkdownLayout`. The map describes `result.markdown` only. Page strings have separate offsets.

Each source slice identifies its story scope, paragraph, source extent, and Markdown extent. Check `exact` before using its `markdownBoundaries`. Interpolate between boundaries only when the source and Markdown distances are equal. Other intervals contain escaping or generated syntax without interior native text boundaries. Reject edit positions that split a UTF-16 surrogate pair.

Paragraph `markdownStart` and `markdownEnd` locate complete constructs, including headings, list markers, quote prefixes, and emphasis delimiters. These construct extents can include generated syntax. Use source slice boundaries to locate native text positions.

The `tables` array maps canonical `tableId` values to complete table constructs. Table extents include GFM divider rows and nested HTML wrappers. Page fragments share one logical table entry. Empty cells retain their table's construct range. Story scopes distinguish body and note tables.

Set `tableSyntax: 'html'` when cells need multiline MDX content. HTML table wrappers retain Markdown cell content and paragraph boundaries. Your consumer must support Markdown inside HTML cells, such as an MDX parser. This option works with all three export entry points and retains source maps. It does not change document layout or the source DOCX.

Use `tableSyntax: 'auto'` to preserve merged cells and structured content while keeping simple tables in GFM. HTML cells retain `colspan` and `rowspan`; continuation cells do not repeat their content. All export entry points retain source maps in this mode. The default remains GFM.

Resolved revision records retain physical grid coordinates for layout and expose logical grid coordinates for export. Deleted columns therefore do not become empty Markdown columns. Canonical cells and physical geometry stay intact.

Generated headings, emphasis delimiters, and table separators have no text slices. Generated drawing and note references can have slices with `exact: false`. The paragraph list includes empty paragraphs that emit no text. The map belongs to this export snapshot. It provides provenance, not an editing API. Reading or generating the map never changes the source document.

Built-in `Quote` and `IntenseQuote` paragraph styles emit Markdown blockquotes outside table cells. Custom inherited quote styles require application normalization.

Hyperlinks preserve sanitized external destinations, internal bookmark references, and tooltips as Markdown titles. Missing bookmark targets retain their references. Unsafe and unresolved external relationships remain plain text. Source maps address label text separately from generated link syntax.

## Detached layouts with images

`exportMarkdownLayout(layout, options?: DetachedMarkdownLayoutOptions)` accepts `imageAssets` alongside the layout options. Retain these assets from `exportMarkdownFrom(session, { images: true })` before disposing the session. Use assets from the same layout revision.

```ts
const layout = await session.layout();
const exported = await exportMarkdownFrom(session, { images: true });
session.dispose();
const result = exportMarkdownLayout(layout, {
  imageAssets: exported.media,
  sourceMap: true,
});
```

The detached exporter uses resolved URLs and occurrence positions from the supplied assets. It does not fetch or extract media. Without `imageAssets`, detached output remains text-only.
